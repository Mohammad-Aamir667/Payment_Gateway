# Payment Gateway Backend
# Security - 05 Token Hashing

---

# 1. Purpose of this Document

Authentication in our Payment Gateway relies on two different types of secrets:

- Passwords
- Refresh Tokens

Although both are secrets, they are fundamentally different.

Passwords are chosen by humans.

Refresh Tokens are generated by the server.

Because of this difference, our project uses different hashing algorithms for each.

- Passwords → bcrypt
- Refresh Tokens → SHA-256

This document explains how Refresh Token hashing works and why we chose SHA-256.

---

# 2. Why Do We Hash Refresh Tokens?

After a merchant successfully logs in, the server generates a Refresh Token.

```
Refresh Token

↓

eyJhbGciOiJIUzI1NiIs...
```

The server returns this token to the browser.

However, the database never stores the original token.

Instead,

```
Refresh Token

↓

SHA-256

↓

Hash

↓

Database
```

Only the hash is stored.

---

# 3. Why Don't We Store Refresh Tokens Directly?

Imagine an attacker gains read access to the database.

If Refresh Tokens were stored in plain text,

```
Database

↓

Refresh Token

↓

Attacker

↓

Authenticated Session
```

The attacker could immediately impersonate merchants.

By storing only the hash,

the original token cannot be recovered from the database.

---

# 4. Hashing vs Encryption

Hashing and encryption are different concepts.

Hashing

```
Input

↓

Hash Function

↓

Fixed-Length Output
```

Encryption

```
Input

↓

Encryption Key

↓

Ciphertext

↓

Decryption Key

↓

Original Input
```

Encryption is reversible.

Hashing is designed to be one-way.

For Refresh Tokens, we do not need to recover the original value.

We only need to verify whether an incoming token matches the stored one.

---

# 5. What is hashlib?

`hashlib` is Python's built-in cryptographic hashing library.

It provides implementations of several hashing algorithms, including:

- SHA-1
- SHA-224
- SHA-256
- SHA-384
- SHA-512
- MD5

In our project, we use SHA-256.

---

# 6. What is SHA-256?

SHA stands for

```
Secure Hash Algorithm
```

SHA-256 is a cryptographic hash function that always produces a fixed-length output.

No matter how large the input is,

the output is always

```
256 bits

=

32 bytes

=

64 hexadecimal characters
```

Example

```
hello

↓

SHA-256

↓

2cf24dba5fb0a30e26e83b2ac5b9...
```

The same input always produces the same output.

---

# 7. Why Do We Encode the Token?

Our helper function is

```python
def hash_token(token: str) -> str:
    return hashlib.sha256(
        token.encode("utf-8")
    ).hexdigest()
```

The Refresh Token is a Python string.

```
str
```

However,

SHA-256 operates on bytes.

Therefore,

we convert

```
String

↓

Bytes
```

using

```python
token.encode("utf-8")
```

---

# 8. What is UTF-8?

UTF-8 is a character encoding.

It defines how characters are represented as bytes.

Example

```
"A"

↓

65
```

Python converts strings into bytes using

```python
.encode("utf-8")
```

before hashing.

---

# 9. What Does hashlib.sha256() Return?

`hashlib.sha256()` does not return the hash itself.

It returns a hash object.

```python
hash_object = hashlib.sha256(
    token.encode("utf-8")
)
```

This object internally stores the computed digest.

---

# 10. What Does hexdigest() Do?

The digest produced by SHA-256 is binary data.

Binary data is not convenient to store or compare.

Calling

```python
.hexdigest()
```

converts the binary digest into a hexadecimal string.

```
Binary Digest

↓

Hexadecimal String

↓

64 Characters
```

Example

```
2cf24dba5fb0a30e26e83b2ac5b9...
```

This string is stored in the database.

---

# 11. How Refresh Token Verification Works

Unlike passwords,

Refresh Tokens are deterministic.

The same Refresh Token always produces the same SHA-256 hash.

During Login

```
Refresh Token

↓

SHA-256

↓

Hash

↓

Database
```

Later, during Refresh or Logout,

the browser sends the original Refresh Token.

```
Browser Cookie

↓

Refresh Token

↓

SHA-256

↓

Hash

↓

Database Lookup
```

If the hash exists,

the session exists.

If not,

the token is invalid or has already been revoked.

---

# 12. Why Don't We Need verify_token()?

Password verification requires

```python
bcrypt.checkpw(...)
```

because bcrypt generates a different hash every time due to random salts.

SHA-256 behaves differently.

```
Input

↓

SHA-256

↓

Always Same Output
```

Verification is therefore performed by

```
Incoming Token

↓

SHA-256

↓

Hash

↓

Compare with Stored Hash
```

No dedicated verification function is required.

---

# 13. Why We Don't Use bcrypt for Refresh Tokens

Passwords are chosen by humans.

Humans choose weak passwords.

bcrypt is intentionally slow to make brute-force attacks expensive.

Refresh Tokens are different.

They are

- randomly generated
- high entropy
- unpredictable

The goal is not to slow down guessing attacks.

The goal is simply to avoid storing the original token.

SHA-256 is therefore an appropriate choice.

---

# Complete Flow

```
Successful Login

↓

Generate Refresh Token

↓

hash_token()

↓

token.encode("utf-8")

↓

hashlib.sha256()

↓

hexdigest()

↓

Store Hash
```

Later

```
Browser Sends Refresh Token

↓

Verify JWT Signature

↓

hash_token()

↓

Database Lookup

↓

Session Found?

↓

Continue
```

Notice that hashing is **not** responsible for proving the token was issued by our server.

JWT signature verification performs that responsibility.

Hashing is used only for secure storage and database lookup.

---

# Why We Didn't Choose Other Designs

## Why not store the Refresh Token directly?

Because anyone with database access could immediately hijack active sessions.

---

## Why not use bcrypt?

Because Refresh Tokens are already random and do not require expensive password hashing.

---

## Why not store the hash as binary?

A hexadecimal string is easier to store, compare, debug, and inspect than raw binary data.

---

# Key Takeaways

✔ Refresh Tokens are never stored in plain text.

✔ SHA-256 is used to hash Refresh Tokens.

✔ `hashlib` provides Python's cryptographic hashing algorithms.

✔ `encode("utf-8")` converts a string into bytes before hashing.

✔ `sha256()` computes the cryptographic hash.

✔ `hexdigest()` converts the binary digest into a readable hexadecimal string.

✔ Refresh Token verification consists of hashing the incoming token and comparing it with the stored hash.

✔ JWT signature verification and token hashing solve two different security problems.
